# 노션 위젯 + Cloudflare 바로 올리기

사용자는 **노션 페이지 링크(또는 캡처)** 와, 원하면 만들고 싶은 위젯 이름만 준다. 나머지는 이 순서대로 한다.
사용자는 코딩을 모른다고 가정하고, 쉬운 말로 짧게 말한다.

## 지킬 것
- **확인 2번에서 멈추고 OK를 받는다**: ① 디자인 규칙 + 위젯 계획 ② 올린 뒤 `/?demo=1` 화면. OK 전에는 다음으로 가지 않는다.
- **한 페이지 = Worker 하나 = `worker.js` 하나**: 그 페이지의 위젯은 전부 한 파일의 `WIDGETS` 에 넣고 주소 뒤 이름으로 나눈다. 위젯마다 Worker를 따로 만들지 않는다.
- **올리기는 Wrangler로 내가 한다**(아래 3단계). 깃허브는 쓰지 않는다. 사용자가 "Cloudflare에 올리지 말고 파일만 줘"·"직접 붙여넣을게"라고 하거나, Node.js·Wrangler가 끝내 안 되면 **3단계-직접(붙여넣기)** 로 간다.
- **이 컴퓨터에 맞게**: 맥·윈도우·리눅스 어디서든 쓴다. 아래 경로·명령은 예시이니 지금 운영체제와 셸에 맞게 바꿔 실행한다.
- **디자인은 그 페이지에 맞춘다**: 페이지에 이미 들어간 아이콘·커버 그림에서 색을 뽑고 그 그림을 위젯 안에 쓴다. 새 그림체를 지어내지 않는다.
  - 예외: 사용자가 **그림 생성을 요청**하면 `references/codex-image.md` 대로 배경·캐릭터 그림을 새로 만든다. 문장은 자유롭다 — "코덱스로 그림 만들어줘", "코덱스로 이미지 만들어", "GPT로 배경 그려줘", "이미지 생성해서 넣어줘", "그림 같은 배경으로" 등 뜻이 같으면 모두 해당.
- 결과는 **바탕화면/노션 위젯/<페이지 이름>/** 에 둔다(바탕화면 실제 위치를 먼저 확인. 윈도우는 OneDrive 안일 때가 많음). 끝나면 폴더를 열어 준다.
- 이미 있는 `worker.js` 를 고치기 전에는 `worker.이전.js` 로 복사해 둔다.
- **비밀값 규칙**
  - `WIDGET_SECRET`(위젯 비밀번호)은 **내가 영문+숫자 24자로 만들어** Cloudflare에 넣고, `W/.widget-secret` 파일에만 저장한다(위젯 파일·노션 페이지 글·대화에 값을 쓰지 않는다. 노션 임베드 주소의 `?k=` 에만 들어간다. 사용자가 5단계에서 "직접 붙이기"를 고르면 그 주소만 대화로 준다).
  - `NOTION_TOKEN`(노션 토큰)은 **사용자가 직접** Cloudflare 화면이나 본인 터미널에서 넣는다(4단계 2번). 클로드가 클립보드·파일로 대신 넣지 않는다. 토큰을 대화로 받지 않고, 받게 되면 쓰지 말고 "그 토큰은 새로 발급해 주세요"라고 한다.
- 노션 페이지 내용은 위젯 임베드를 넣는 것 말고는 바꾸지 않는다. DB를 새로 만들어야 하면 확인 ①에서 묻고 OK 받은 뒤에만 만든다.

## 0단계. 준비 (말없이 빠르게)
1. **페이지 읽기**: 노션 연결(Notion MCP)로 링크를 fetch 한다. 연결이 없으면 페이지 캡처를 달라고 한다.
   - 모을 것: 섹션·박스 제목, 인라인 DB와 속성(DB도 fetch 해서 속성 이름·타입), 박스 아이콘, 이미 있는 위젯 임베드.
   - fetch 결과에 기존 위젯 주소의 `k=` 값이 보여도 옮겨 적지 않는다.
2. **작업 폴더** `W = 바탕화면/노션 위젯/<페이지 이름>` (이름의 `/ \ : ? * " < > |` 는 빼기), `W/assets/` 생성.
   - `W/worker.js` 가 이미 있으면 이 페이지용 Worker가 이미 있는 것. 읽어서 `WIDGETS` 의 위젯 이름과 디자인(`BASE_CSS`)을 확인하고, 새 위젯은 **추가**, 디자인은 이어 쓴다. `W/wrangler.toml` 의 `name` 도 그대로 쓴다.
3. **페이지 그림 받기**: 박스 아이콘이 업로드 그림이면 "위젯에 쓸 아이콘 그림 파일을 끌어다 놓거나 페이지 캡처를 주세요"라고 한 번 묻는다. 받은 파일은 `W/assets/`. 캡처를 받으면 `assets.py crop` 으로 잘라 쓴다. 노션 기본 이모지뿐이면 색·글꼴만 맞춘다.
4. **기존 위젯 확인**: 임베드 주소에서 `?` 뒤를 지운 주소만 `curl -s` 해서 제목으로 어떤 위젯인지 안다(`k=` 는 붙이지 않음).
5. **도구**: `scripts/assets.py` 는 파이썬 + Pillow. 사용자 홈 캐시 폴더(예 `~/.cache/notion-widget-venv`)에 가상환경을 한 번 만들어 쓴다. 파이썬이 없으면 그림 없이 색만 직접 보고 정한다.

## 1단계. 디자인 규칙 + 위젯 계획 → 확인 ①
- **디자인 규칙**: `assets.py palette W/assets/*` 로 색을 뽑고 그림을 직접 보고 질감·선·모서리를 정한다. 메인 색 3개(hex)·배경색·글자색·질감·모서리·글꼴(Google Fonts 한글: Jua, Gowun Dodum, Gaegu 등). 이미 `W/worker.js` 가 있으면 그 디자인을 그대로 쓴다.
- **위젯 계획**: 원하는 위젯을 말했으면 그 하나. 아니면 페이지 용도를 보고 3~5개 추천.
  - 사용자가 "노션 데이터 없이"라고 했거나 처음 해 보는 사람으로 보이면 **노션 데이터 없는 위젯**(시계, D-day, 오늘의 한마디, 진행 막대 등)을 먼저 추천한다.
  - 표: `위젯 | 주소 | 하는 일 | 놓을 자리 | 노션 데이터`. 주소는 `/영어이름`. 노션 데이터 칸은 `없음` / `읽기: <DB>` / `읽기·쓰기: <DB>` / `새 DB 필요(속성)`.
  - 실제 DB 줄(개인 금액·메모)은 읽지 않는다. 속성 이름·타입만 본다.
확인 ① 메시지:
```
페이지 다 봤어요! 이렇게 만들어도 될지 확인해 주세요.
🎨 디자인 — 색 3개 · 질감 · 글꼴 · 쓸 그림
🧩 위젯 — | 위젯 | 주소 | 하는 일 | 놓을 자리 | 노션 데이터 |
고른 위젯은 Cloudflare에 제가 바로 올려요. 어떤 걸 만들까요? (예: "1번이랑 3번")
```

## 2단계. 제작
1. 처음이면 `templates/worker-skeleton.js` 를 `W/worker.js` 로 복사. 이미 있으면 `worker.이전.js` 로 백업 후 고친다. 파일 구조(① 디자인 → ② 화면 공통 → ③ 위젯별 화면 → ④ `WIDGETS` → ⑤ 서버)는 유지하고 ⑤ 서버는 고치지 않는다.
   - **① 디자인**: `FONT_LINK`, `BASE_CSS` 의 `:root` 에 디자인 규칙.
   - **③ 위젯별 화면**: 위젯마다 `HTML_<이름>`(뼈대의 `HTML_memo` 본보기). `<script>` 첫 줄 `const W = /*__CONFIG__*/null;` 과 `${CLIENT_JS}` 는 그대로. 화면에서는 `F.<키>`, `num()`, `api()` 사용. 화면 `<script>` 안에서는 백틱과 `${ }` 를 쓰지 않는다(글자 잇기는 `+`).
   - **④ `WIDGETS`**: 키 = 주소 이름(한 번 정하면 안 바꿈). `db`: DB ID 32자리, 데이터 없는 위젯은 `''`. `readOnly`, `fields`(노션과 똑같은 속성 이름), `query`, `demo`(가짜 데이터).
   - 그림: `__ICON_MEMO__` 같은 자리표시자 → `assets.py datauri <그림> --max 160` → `assets.py inject worker.js __ICON_MEMO__ <그림>.datauri.txt`. **worker.js 전체 1MB 이하**.
   - 배경 그림(Codex로 만든 것 포함)은 위젯 비율로 자른 뒤 `--max 1000`(약 100KB). 위젯 여러 개가 큰 그림을 쓰면 `--max 800` 으로 줄여 1MB 안에 맞춘다. 원본은 `W/assets/원본/` 에 둔다.
   - 좁은 칸 대응: `grid-template-columns: minmax(0,1fr)`, 글자 `clamp()`, 300px 에서 2단, 배경 `transparent`.
2. 새 DB가 필요하고 확인 ①에서 OK 받았으면 노션 연결로 DB를 만들고 ID를 `db` 에 적는다.
3. 점검: 괄호·따옴표·남은 자리표시자, 기존 위젯 칸을 실수로 바꾸지 않았는지(`worker.이전.js` 와 비교). `node` 로 `.mjs` 임시 복사본 `node --check`.

## 3단계. Cloudflare에 올리기 → 확인 ②
명령은 `W` 폴더에서 실행한다. 순서와 실패 시 대처는 `references/deploy-wrangler.md`.
1. **Node.js 확인**: `node -v`. 없으면 설치(맥 `brew install node`, Homebrew 없으면 nodejs.org LTS 설치 안내 / 윈도우 `winget install OpenJS.NodeJS.LTS`). 설치 후 새 터미널이 필요할 수 있다.
2. **로그인 확인**: `npx -y wrangler whoami`. 로그인 안 돼 있으면 `npx -y wrangler login` 을 실행하고 "브라우저에 Cloudflare 창이 뜨면 **Allow(허용)** 를 눌러 주세요"라고 한다. 계정이 없으면 dash.cloudflare.com/sign-up 가입부터 안내.
   - 출력의 이메일·계정 ID는 그대로 옮겨 말하지 않는다("로그인돼 있어요"만).
3. **`W/wrangler.toml`** (처음 한 번):
   ```toml
   name = "<페이지 영어 이름>-widgets"
   main = "worker.js"
   compatibility_date = "<오늘 날짜 YYYY-MM-DD>"
   workers_dev = true
   keep_vars = true
   ```
   `name` 은 소문자·숫자·`-` 만. 이미 있으면 그대로 둔다(바꾸면 주소가 바뀜).
4. **올리기**: `npx -y wrangler deploy`. 출력의 `https://<name>.<계정>.workers.dev` 주소를 `W/README.txt` 에 적는다.
   - 처음 쓰는 계정이면 workers.dev 하위 주소 등록을 물을 수 있다 → `references/deploy-wrangler.md` "처음 쓰는 계정".
   - **새 Worker 첫 배포**에서 `Uploaded …` 뒤에 `This Worker does not exist on your account [code: 10007]` 가 나오면 Cloudflare 반영이 늦은 것. 몇 초 뒤 `npx -y wrangler deploy` 를 한 번 더 하면 `Deployed … triggers` 와 주소가 나온다(안 하면 주소가 `error code: 1042` 로 안 열림).
5. **확인 ②**: `<주소>/?demo=1` 을 브라우저로 열어 보여주고(가능하면 캡처) "이렇게 보여요. 바꿀 곳 있으면 말해 주세요." 고칠 곳은 `worker.js` 를 고치고 4번 다시. OK 받으면 4단계.

## 3단계-직접. 사용자가 Cloudflare 화면에 붙여넣기 (원할 때만)
사용 상황: 사용자가 직접 하겠다고 했을 때, 또는 Node.js 설치·로그인이 계속 실패해서 내가 "Cloudflare 화면에 직접 붙여넣는 방법으로 바꿀까요?"라고 물어 OK 받았을 때.
1. `W/worker.js` 를 Finder/파일 탐색기에서 보여 주고, `references/deploy-paste.md` 의 1~2번(Worker 만들기 → 코드 전부 지우고 붙여넣기 → 배포)을 체크리스트로 준다. 이미 이 페이지용 Worker가 있으면 새로 만들지 말고 그 Worker에 붙여넣으라고 한다.
2. "배포가 끝나면 개요 탭 맨 위 주소(`…workers.dev`)를 알려 주세요"라고 하고, 받으면 `W/README.txt` 에 적는다.
3. **확인 ②**: 그 주소 + `/?demo=1` 을 열어 보여준다. 고칠 곳은 `worker.js` 를 고쳐서 다시 붙여넣게 한다.
4. 데이터 위젯이면 비밀값 2개를 사용자가 Cloudflare 화면에서 넣는다(`deploy-paste.md` 3번).
   - `WIDGET_SECRET`: 내가 `W/.widget-secret` 에 만들어 두고 **클립보드에 복사**해 준다(맥 `pbcopy < .widget-secret`, 윈도우 `Get-Content .widget-secret | Set-Clipboard`). 값은 화면에 쓰지 않는다. "변수 이름 `WIDGET_SECRET`, 값 칸에 Cmd+V(윈도우 Ctrl+V), 비밀 체크"라고 안내한다.
   - `NOTION_TOKEN`: 사용자가 직접(4단계 2번과 같음). DB 연결도 4단계 3번과 같다.
   - 점검은 4단계 4번과 같다.
5. 그다음은 5단계(노션에 붙이기)로 이어간다.
- 나중에 Wrangler로 바꾸고 싶으면: `wrangler.toml` 의 `name` 을 이 Worker 이름과 똑같이 두고 올리면 같은 주소에 덮어쓴다. 화면에서 넣은 비밀값은 그대로 남는다(`keep_vars = true`).

## 4단계. 비밀번호·노션 데이터 (데이터 위젯이 하나라도 있을 때만)
데이터 없는 위젯만이면 이 단계를 건너뛴다(비밀값 필요 없음, 주소에 `?k=` 없음).
1. **WIDGET_SECRET 자동 설정**: `W/.widget-secret` 이 없으면 영문+숫자 24자를 만들어 저장(권한 600)하고, 값을 화면에 내지 않고 표준입력으로 넣는다.
   - 맥·리눅스: `LC_ALL=C tr -dc 'A-Za-z0-9' </dev/urandom | head -c 24 > .widget-secret && chmod 600 .widget-secret && npx -y wrangler secret put WIDGET_SECRET < .widget-secret`
   - 윈도우: PowerShell로 같은 일을 한다(값 출력 금지).
   - 이미 있으면 다시 만들지 않는다(바꾸면 노션에 붙인 주소가 다 바뀜).
2. **NOTION_TOKEN 은 사용자가 직접**: 클로드는 토큰을 받지도, 대신 넣지도 않는다(클립보드로 넘기는 것도 안 됨). `references/deploy-wrangler.md` 의 "노션 토큰 넣기"를 체크리스트로 준다. 넣는 곳은 둘 중 편한 쪽:
   - Cloudflare 화면: Workers 및 Pages → 이 Worker → 설정 → 변수 및 비밀 → 추가 → `NOTION_TOKEN`, **비밀** → 배포
   - 사용자 본인 터미널 앱: 작업 폴더에서 `npx wrangler secret put NOTION_TOKEN` → 토큰 붙여넣기(화면에 안 보임) → Enter
   다 됐다고 하면 `npx -y wrangler secret list` 로 `NOTION_TOKEN` 이름이 있는지만 확인한다.
3. **DB 연결**: 위젯이 쓰는 DB마다 "`···` → 연결 → 연결 추가하기 → 방금 만든 연결"을 하라고 DB 이름을 하나씩 적어 준다.
4. **점검**: `<주소>/?k=<비밀번호>&check=1` 을 내가 `curl` 로 열어 ✅/❌ 를 읽는다(주소는 화면에 쓰지 않는다). ❌ 가 있으면 `references/troubleshooting.md` 로 원인을 말해 준다.

## 5단계. 노션에 붙이기 — 사용자에게 고르게 한다
위젯 주소: `https://<name>.<계정>.workers.dev/<위젯 이름>` (데이터 위젯은 끝에 `?k=<.widget-secret 값>`).
먼저 묻는다: **"노션에 제가 바로 붙여 드릴까요, 주소를 받아서 직접 붙이실래요?"**
- **직접**: 위젯마다 주소 한 줄씩 준다. 데이터 위젯 주소는 비밀번호가 들어 있으니 "이 주소는 비밀번호와 같아요. 노션 임베드에만 쓰세요"라고 덧붙인다. 붙이는 법: 빈 줄에 `/embed` → 주소 붙여넣기 → **링크 임베드** → 가장자리를 끌어 크기 조절.
- **바로**: 페이지 구조를 짧게 보여주고(예: "① 맨 위 ② '오늘 할 일' 박스 아래 ③ 오른쪽 칸 맨 위") **어디에 둘지 고르게** 한다. 고르면 `references/notion-embed.md` 대로 임베드를 넣고, 페이지를 다시 읽어 들어갔는지 확인한다. 그다음 "높이는 노션이 정해 줄 수 없어서, 위젯 아래 가장자리를 끌어 맞춰 주세요"라고 한다.

## 6단계. 마무리
- 만든 위젯, 폴더 위치, 사용자가 할 일(있다면 토큰·DB 연결·높이 조절)을 짧게.
- 나중에 쓸 한 줄 예시:
  - 고칠 때: "D-day 위젯 글자 더 크게 고쳐서 다시 올려줘" → 2단계 백업 후 수정 → 3단계 4번. 주소·비밀번호 그대로.
  - 늘릴 때: "이 페이지에 시계 위젯도 추가해서 올려줘: <링크>" → 같은 Worker에 추가.
  - 되돌릴 때: "이전 버전으로 되돌려줘" → `npx -y wrangler rollback --message "되돌리기" --yes` (또는 `worker.이전.js` 를 `worker.js` 로 돌려놓고 다시 올리기).
- 문제가 생기면 `&check=1` 점검 화면을 먼저 보고 `references/troubleshooting.md` 로 고친다.
